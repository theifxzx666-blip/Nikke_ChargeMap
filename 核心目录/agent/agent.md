## 2026-10-28 · 第二台设备全量采集 P1+P2 + 章节归档

### 结果
- 采集 **112 个**（P1 96 + P2 16），69.8 分钟，**0 失败**；P3 变体 62 个未采（用户暂不需要）。

- 验收全绿：`paths.py --check` 缺件 0；`gen_catalog.py --check` 通过（提示 0）；
  tris 全 > 0；**112/112 顶点比 ≥ 1.5**；covers 全 5；贴图全 > 0。
- 新增 `工具/采集/apply_chapters.py`（区域→章节归档）、`docs/12-全量采集落地与章节归档.md`。

### 关键决策及理由
1. **章节识别分两层**：章节级（`CampaignChapterTable.chapter` + `field_id` 区域）**可做**；
   关卡级（哪一关用哪张 sbg）**客户端无表**。`docs/11` §1 原写「第 N 章用哪张背景：没有」
   易被读成「章节也识别不了」，已改为两行分列。
2. **共用区域不拆**：同区域被多章共用（cityforest 7 张图对 11 章、desert 14 张对 6 章），
   拆到章必然靠猜，故落首个章号目录 + `_章节.json.chapters` 记全部共用章号。
   已核验的 `H34/H35/H39` 目录名不动（文档与页面都引它）。
3. **非主线区域单列 `N_<区域>`**：14 个区域在章节表里没有 `field_id`（塔/模拟/海洋/火山/墓地…）。
   `N_cityforestunder` / `N_cityforestunderelevator` / `N_arkcityday` 疑似主线变体，
   标 `note` 待核，未写 chapters。
4. **重复场景保留旧键**：13 组同 arena 重复保留旧键旧目录名（`001/c001/bbg008/…`），
   内容换成本轮新采的；旧内容进 `回收站/_v15重复_20261028/`。

### 踩坑
1. **GitHub 直连抖动**：`git fetch` 报 `Empty reply from server` / `schannel missing close_notify`，
   `raw.githubusercontent.com` 超时；改用 `codeload.github.com/.../tar.gz` 单流下载（约 40 KB/s，
   46.8 MB / 19 分钟）。`-C -` 续传对动态 tarball 无效（返回 200 且 0 字节）。
2. **断点续跑判据错误（v15 缺陷）**：跳过判定按 `--chapter` 拼路径，场景归档到 `H35_*` 后
   再跑 `--run` 会判「没采过」→ 整批重采。已改为以 registry 为准（`_done(short, stem)`），
   兼容旧键与 `short_name()` 两套键域，实测 5 个场景全部跳过、0 次 `adb dd`。
3. **目录改名后装配文件名不匹配**：把新采目录并入旧键目录后，内部仍是 `assembly_sj001.json`，
   `PATH.assembly('001')` 找不到 → `gen_catalog --check` 报 13 项「缺 assembly」。
   需同步改 assembly/glb/meta 文件名与 `slots.json` 的键。
4. **旧母鲸三场景是 `z=zmin` 修复前版本**：7974/6953/6320 面 vs 本轮 31932/27968/25620，
   相差约 4 倍；`docs/08` 的口径已过时，重采后才是全量。

### 遗留待办

- `N_cityforestunder` / `N_cityforestunderelevator` / `N_arkcityday` 待实机认图定章。

## 2026-10-28 · 第三轮：双语目录名 + 全貌预览 + 全览图

### 用户的三条要求
1. 目录名要同时有英文原名与汉化译名（裁决形态：**中文在前** `H35_沼泽丛林_swamplandjungle`）
2. 每个场景补一张 PNG 全貌预览
3. 补一张全览图

### 结果
- 25 个章节目录改名完毕（脚本 `工具/采集/rename_chapters.py`，`--dry` 可复跑校验）
- 官方章节名 0~48 章取到（国服 `Locale_Stage.lss`），落 `资源库/共享依赖/其他/chapter_names_zh.json`
- 112 张预览图 `正式产物/场景图/预览/<arena>.png`（1920×1080）
- 全览图 `正式产物/场景图/全览图/`（分卷 + md 索引）
- 三类图分区：`充能图/`（43 张阵位图）· `预览/` · `全览图/`

### 关键决策
- **英文段只认 bundle 的 region**，不用章节表那套（`cityforestcrystal` ≠ `cityforestundercrystal`）。
- **章节名不进目录名**：35 章官方名是「沟通」，跟战场长相无关。
- 中文名三级来源 `official / inherited / translit`，`translit` 在清单末尾单列待核，不静默当官方。
- **全貌机位俯角固定 22°**，靠距离递增容纳；换俯角会让同批图没法横向比。

### 踩坑（本轮新增 6 条，全部写进代码注释与 PROMPT §21）
1. **`cam.far` 改了没 `updateProjectionMatrix()`** → 整场景被远裁剪，画面纯灰，且看不出是裁剪。
2. **天空球球心留在原点** → 远景机位看到球的下半部，画面凭空多一块灰圆；改为球心跟随相机。
3. **`hud=0` 没关 `#scrim`** → 每张图左上角带一块渐变暗角（用户第一眼就看出来了）。
4. **距离公式两头算宽** → d 偏大 45%，场景缩成一小块；水平只算 `sz.x`，垂直算 `y·cosθ+z·sinθ`。
5. **个别场景 bbox 被超长物体撑爆**（`wc003` 深 2039 vs 普通 100~200）→ 相机陷进场景内部或退到
   2000 外成一个小点；用 mesh 中心的 2%~98% 分位收缩，剔掉 2% 离群。
6. **`ground_tile()` 只认 `_ground01_c.png`** → 38 个场景地面被静默丢弃（`ground_c` 29 个、
   `ground02_c` 20 个、`ground03_c` 4 个），图里场景「飘在空中」。这是用户问「是不是缺素材」的真因；
   贴图本身不缺（glb 里内嵌，`uri` 计数 0）。另 5 个 boss/变体场景的物件全挤在一个 z 桶，
   剖面退化，补了平带兜底。
