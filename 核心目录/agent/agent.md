## 2026-11-14 · 分析层接入真机位 + 五站位实机图验证

### 目标
用户给了 tw003 五个站位的实机截图，要求据此确认视角是否还原，并推进到重算。

### 结果
1. **画幅修正**：五张实机图含 Windows 窗口边框，1920×1146 → 裁边后 **1848×1074 = 1.7207**，
   不是 16:9。说明窗口化时游戏按客户区比例渲染，设置里的「画面比例 16:9」不锁视口。
   已写入 `参数真源.json → viewport.observed_window_aspect`；分析基准仍是 1600×900（16:9），
   横向差 3.2%，可直接换算。
2. **`scan_px.py` 接入真机位与偏航**：
   - 新增 `rot_in / rot_out`（Unity yaw 绕 +Y 的世界↔局部互逆变换），
     `camera_depth` / `to_px` 加 `yaw` 参数，反投影按 `R_y(θ)` 转回世界
   - 机位改读 `camera_aim` / `camera_hide`，新增 `--stance=aim|hide`，
     旧 `camera_position` 只作兜底并告警
   - `px_*.json` 增加 `cam_yaw` / `cam_source` / `stance`
   - 自测：互逆误差 ≤8.9e-16；yaw=90° 时 +X 点落画面正中；yaw=4° 把偏右 0.7m 的点从 px 909 拉回 854
3. **tw003 五阵位试点**（新增分析）：8 / 10 / 11 / 8 / 10 点，共 47 点。闸门 112 场景 · 48 组 · 536 点位。
4. **与实机对照**：中央圆环、左侧塔状物、右侧立柱、地平线的水平与纵向位置逐一对齐；
   点位落在对应的可破坏结构上；近景 `cover_object` 按规则排除（不可击穿）。

### 关键决策
- 不再用「远景是否对齐」当唯一判据：实测五张实机图的远景两两相关只有 0.485（不是 1.0），
  说明远景**不是**完全跟随相机的卷轴层，确实随站位位移；但像素级对比被角色/HUD/战斗特效污染
  （中景区域实机相关 0.141 vs 渲染 0.529），所以改用「静态结构位置 + 点位落点」双重判据。
- 分析基准保留 1600×900（16:9），不改成 1.7207：像素主键已有 489 点建立在此基准上，
  且纵向 FOV 相同，横向换算无损。

### 踩坑
- 重写 `参数真源.json` 的 camera 段时把 `near_clip` / `far_clip` 删掉了，
  `scan_px.py` 一导入就 `KeyError: 'near_clip'`。已补回顶层。
- bash 里 `for spec in "1 1" "1 0"; do set -- $spec` 会覆盖 `$1`，导致文件名与 URL 参数一起被改，
  两张图渲染成同一张。改用独立循环变量。

### 待办
- verify / audit 阶段未跑（130s/阵位 × 5）；15 个老场景（001~005 / bbg008·009 / c001~005 / mw001~003）
  仍是旧锚点 + 无偏航的结果，需按新机位重算。
- `render_views.py` / `scene_reel.py` 已能读参数真源，但**未传 rig 参数**，
  出图默认会走 `fp.cam`（px json 里的真机位），一致性待确认。
- 112 个场景里还有 96 个从未分析。

## 2026-11-14 · 真实机位落库：从机位树读到 slots.json 与渲染器

   `Transform + CinemachineVirtualCamera + CinemachineRecomposer`，**没有 Transposer**，

   `wl004`/`mw003`/`cu005`/`ce004` 单点偏移、`ocebg001001` 带 1.3575 缩放）。
4. **新增 `工具/采集/build_slot_rigs.py`**：读 `参数真源.json → camera.rig`，逐场景按自己的

   旧 `camera_position` 保留但加 `anchor_note` 标注「机架锚点，非相机」。

   有点位数据时仍用点位自带 `cam`（点位是按它算的）；`PITCHQ='auto'`、显式 `pitch=`/`yaw=` 的优先级都保留。

### 踩坑（本轮新增 6 条，全部写进代码注释与 PROMPT §21）
1. **`cam.far` 改了没 `updateProjectionMatrix()`** → 整场景被远裁剪，画面纯灰，且看不出是裁剪。
2. **天空球球心留在原点** → 远景机位看到球的下半部，画面凭空多一块灰圆；改为球心跟随相机。
3. **`hud=0` 没关 `#scrim`** → 每张图左上角带一块渐变暗角（用户第一眼就看出来了）。
4. **距离公式两头算宽** → d 偏大 45%，场景缩成一小块；水平只算 `sz.x`，垂直算 `y·cosθ+z·sinθ`。
5. **个别场景 bbox 被超长物体撑爆**（`wc003` 深 2039 vs 普通 100~200）→ 相机陷进场景内部或退到
   2000 外成一个小点；用 mesh 中心的 2%~98% 分位收缩，剔掉 2% 离群。
6. **`ground_tile()` 只认 `_ground01_c.png`** → 38 个场景地面被静默丢弃（`ground_c` 29 个、
   `ground02_c` 20 个、`ground03_c` 4 个），图里场景「飘在空中」。这是用户问「是不是缺素材」的真因；
   贴图本身不缺（glb 里内嵌，`uri` 计数 0）。另 5 个 boss/变体场景的物件全挤在一个 z 桶，
   剖面退化，补了平带兜底。
