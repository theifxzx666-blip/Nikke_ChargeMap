# NIKKE 地图 · 阵位重算与点位分层 · 执行 Prompt

> **版本**：v1.0（2026-10-27）
> **场景**：用户反馈「选了掩体 / 改了显示个数，**图片上什么都不变**」
> **上位契约**：`F:\Codex\Nikke\AGENTS.md` · `..\AGENTS.md` · `..\docs\07-阵位与视角.md`（本技能的方法论文档）
> **本场景定位**：**S-VIEW**。解决两个不同层次的问题 ——
> ① 数据层：像素坐标只算过一套机位（换掩体等于换了相机，坐标全废）；
> ② 渲染层：点位被烘进图片像素，前端改不了。
> **红线**：**点位标注永远不许画进图片**。图片只出纯场景。

## 0 先分清两类「不变」

症状一样，病因完全不同，**先判定再动手**：

| 症状 | 病因 | 归属 |
|---|---|---|
| 换了掩体，视角/表格变了，但**图上的圆点位置和数量不动** | 数据只有 `cover_3` 一套 | 数据层 → §1 |
| 点了「显示 8 个 / 全部」，**图上圆点数不变** | 圆点是图片像素 | 渲染层 → §2 |

两者可以同时存在。2026-10-27 先只修了数据层，用户复述「还是老问题」，才发现渲染层才是主因。

## 1 数据层：让每个阵位有自己的答案

### 1.1 阵位差异有多大（拆包 `slots.json`，15 个战场共用一套布局）

| 阵位 | 相机 x, z | 相对 3 号位 |
|---|---|---:|
| cover_1 | −4.8, 0.0 | −5.4 m |
| cover_2 | −2.1, −2.0 | −2.7 m |
| **cover_3** | **0.6, 0.0** | **0（游戏进图默认）** |
| cover_4 | 3.3, −2.0 | +2.7 m |
| cover_5 | 6.0, 0.0 | +5.4 m |

相机横跨 **10.8 m**，20 m 目标上就是 **±15° 方位差**。所以「照 3 号位的点位表去站别的掩体」是错的。

实测同一战场换阵位，达标点数差到 **2.3 倍**（002：2 号位 14 个 / 1 号位 24 个）。

### 1.2 四个脚本必须同时支持 `--view`

```bash
PY=/c/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python
cd 数据
$PY scan_px.py   001 --view=cover_1
$PY verify_px.py 001 --view=cover_1 --sim=300
$PY audit_px.py  001 --view=cover_1
$PY sim_charge.py 001 --view=cover_1
```

产物命名：`px_<arena>_<view>.json`、`audit_<arena>_<view>.json`。
`view=cover_3` 时**额外**写一份 `px_<arena>.json`（兼容旧脚本与旧页面）。

> 旧实现是 `view = "cover_3" if "cover_3" in orgs else sorted(orgs)[0]` —— 写死。
> 这是「换掩体图不变」的第一层原因。

### 1.3 批量跑，别手写循环

```bash
$PY batch_views.py --jobs=6     # 组间并行 6 路 + 断点续跑（已有产物默认跳过）
```

- 串行 **87 分钟** → 并行 **16 分钟**（12 核机器）。
- 断点续跑判定：目标 json 里 `verify.field_sim` 存在即视为完成。
- 空战场（0 个达标点）必须写全 0 结果，否则 `sim_charge.py` 抛 `IndexError`，整组被判失败。

### 1.4 出图也按阵位

```bash
$PY render_views.py --force     # → render/fp_<arena>_cover_<N>.webp
```

**`viewer/fp.html` 的相机必须能从 `slots.json` 直取**，不能依赖 `px_*.json` ——
否则批处理正在重写 `px_*.json` 时出图会读到半成品。

```js
// ?dots=0 时走 nodata 模式：只按 slots 的相机摆位，不加载点位
const SC = (slots[ARENA] || {})[VIEWQ] || {};
const C = fp.cam || (SC.camera_position || [])[0];   // ← 注意多一层数组
```

`slots.json` 里是 `camera_position: [[x, y, z]]`。取 `C[0]` 会得到 `[-4.8,0,0]` 这一层**数组**，
再当成坐标用就是 `NaN` → 相机跑到无限远 → 雾把整屏刷成灰色，但脚本仍然报成功。
**出图脚本必须加空白检测**（PNG < 200KB 视为失败并打印 URL）。

## 2 渲染层：图归图，点归点

### 2.1 为什么

`viewer/fp.html` 的点位是 three.js 的 `dotSprite` / `labelSprite`。
截图时它们和其他像素一起被写进 `.png`。页面上的 `<img>` 是**静态位图**，
前端无论怎么切控件都不可能重绘它 —— 这不是 CSS/JS 能解决的，是架构问题。

### 2.2 三段式改造

| 段 | 改法 | 落点 |
|---|---|---|
| 出图 | `?dots=0&hud=0&nodata=1` | `viewer/fp.html` + `render_views.py` |
| 点位 | `mark_html()` → 绝对定位 `<i class="dm">` | `gen_fp_page.py` |
| 切换 | `.cvwrap` 容器 + `data-cv`，JS 切显隐 | 同上 |

**`mark_html()` 的坐标换算**（图片 `width:100%` 显示，百分比自动跟随缩放，不需要 JS 重算）：

```python
w = d.get("w") or 1600
h = d.get("h") or 900
left = px[0] * 100.0 / w
top  = px[1] * 100.0 / h
# data-no = 序号（复用已有「显示几个」筛选）
# data-ss = "c1,c2,c3,c4,c5" 各阵位段数（复用已有「跨阵位对照」打灰）
```

**关键设计：复用已有的筛选属性，不新写一套。**
现有 `apply(n)` 会对所有带 `[data-no]` 的元素生效、`setSlot(s)` 会对所有带 `[data-ss]` 的元素生效 ——
只要给叠加层元素加上这两个属性，它自动跟随，零改动。

### 2.3 容器分组

```
section.ar#a001
├── .nbar.cbar            机位切换条（cover_1~5，默认 cover_3）
└── .cvwrap[data-cv=cover_1]   ← 图 + 叠加层 + 表 + 明细，整套一份
    .cvwrap[data-cv=cover_2]
    ...
```

切机位 = 切 `.cvwrap` 的 `display`，图、圆点、表格、达标点数、锥宽**一起换**。

### 2.4 出图后的验证：只看 HTML 结构是不够的

用户抱怨的正是「结构看着对，操作起来不动」。**必须真机点击**：

```bash
node check_page_marks.mjs     # 无头 Chrome + CDP，真实 click 后读 DOM 再截图
```

断言项：

| 操作 | 期望 |
|---|---|
| 默认 | 图上圆点 5 个（①~⑤）、表格 5 行 |
| 点「全部」 | 圆点 12 个（①~⑫）、表格 12 行 |
| 跨阵位对照 = 2 号 | 圆点仍 12 个，其中 N 个 `dim` 变灰划线 |
| 切「1 号位」 | 全部重算，第一个圆点的 `left` 百分比应变化（如 50.91% → 59.84%） |

截图要人眼再看一遍 —— 数字对不代表画面里没有两套重叠的标记。

## 4 踩坑

| 坑 | 处置 |
|---|---|
| `slots.json` 相机是 `[[x,y,z]]` | 取 `camera_position[0]`，并给出图脚本加空白检测 |
| 出图依赖 `px_*.json` 会被批处理打断 | `dots=0` 时走 `nodata` 模式，直接从 slots 取相机 |
| `.gitignore` 把 `render/*` 全挡了 | 加 `!数据/render/fp_*.webp` 例外，否则图推不上去、线上页面空图 |
| 叠加层坐标写死 1600×900 | 必须用 `d["w"] / d["h"]` 现算，别信默认值 |
| 只验证 HTML 结构 | 必须 CDP 真机点击 + 人眼看截图 |
| 手写 `for v in cover_1..5` | 用 `batch_views.py`，并行 + 续跑 |
