### 根因与修法
- **章节号取错字段**：`CampaignChapterTable.id` 是主键，真章节号是 `chapter`（= `chapter_id − 1`）。
  沼泽丛林 `chapter_id=36` / `chapter=35` / 剧本 `d_main_35_*` / `fcbg_swamplandjungle_001`；
  晶化城市森林 `chapter_id=35` / `chapter=34` / `d_main_34_*` / `fcbg_cityforestcrystal_007`。
  旧文件名 `H36-35*` 其实一直是对的含义（chapter_id 36 / chapter 35），只是中文标题写错。
- **z=zmin 丢面**：`build_assembly.py` 只导出 z 最小一层顶点（单面平板减半优化），盒状件侧壁
  三角面跨两层被整片丢掉 → 只剩 24.5%，射线从侧壁缺口穿过 → 遮挡失效、段数虚高。
  修后沼泽 001 三角面 15,276 → 62,070（4.06×）。
- **发白**：`viewer/fp.html` 把材质 `color` 乘 `bright`（默认 1.18）且 `material.fog=false`。
  改 bright=1.0、开 `FogExp2(0.4627, 0.006)`、画布 `contrast(1.05) saturate(1.06)`、天空球不参与雾。
- **雾片糊成灰块**：`export_glb.py` 一律 `alphaMode=MASK, cutoff=0.5`，`*_fog01`（alpha 均值 0.16、
  86% 像素 <128）被当不透明矩形。改为按不透明像素占比分流（≥50% MASK，否则 BLEND）。
- 另加 `_col` 碰撞网格过滤（否则射线撞隐形地板，段数全归零）。

## 按阵位（掩体）重算 + 图上的点位改成 DOM 叠加层（已推送 9b488b1）

### 用户两次反馈
1. 「我即使选了点位数量以及掩体，图片上并不会发生变化；游戏里默认是 3 号位，不同掩体视角不一样」
2. 「还是老问题，我指的是图片上标注的点位，切换点位之后图片都不会刷新」

第 1 次我只理解成「换掩体要换图」，做了 5 阵位重算出图；第 2 次才点透：
**要变的是图上的点位标注，不是那张风景图**。

### 四个根因（前三个治不了第四个）
1. `scan_px.py` 写死 `view = "cover_3"` —— 5 个掩体相机横跨 10.8m（20m 目标 ±15°），只算一套
2. `pick(k)` 只重排表格、高亮 c1~c5 列，从没碰图
3. `render/` 每个战场只有一张 3 号位静图
4. **点位是 three.js sprite（`dotSprite`/`labelSprite`），截图时烘进 webp 像素** ——
   位图不认识 DOM，数据再全也没法重绘。**这是加多少张图都解决不了的**，必须换渲染方式。

### 修法：图归图，点归点
- `fp.html` 新增 `dots=0`（不画 sprite）、`nodata=1`（不读 px json，相机改从 slots.json 取，
  这样出图不被正在重算的 json 卡住）
- `render_views.py` 出纯场景图（`dots=0&hud=0&nodata=1`）
- `gen_fp_page.py` 新增 `mark_html(d)`：把 `px`（1600×900 基准屏幕像素）换算成百分比，
  输出绝对定位 `<i class="dm">`；`data-no` 复用现有 `apply(n)` 过滤，`data-ss`（c1~c5 段数）
  让 `pick(k)` 打 `.off`（灰+划掉）/`.faint`（半透明）
- 配色按稳态段数：5+ 金 / 4 薄荷 / 3 蓝 / 2 灰 / <2 暗；hover 出编号+段数+首击距离+c1~c5
- boss 小图（bbg008/bbg009）走 `boss_marks()` 接同一套叠加层

### 加速与健壮性
- `batch_views.py` 改 **组间并行**（`--jobs=6`，12 核）：87min → **16min**；加断点续跑
  （判据 `verify.field_sim` 存在 + audit 文件存在）
- `sim_charge.py`：0 达标点阵位原来 `IndexError` 整组判失败（bbg008 1/2/3 号位），
  现在写全 0 的 `field_sim`；`report()` 同步防空
- `render_views.py` 加空白检测：PNG < 200KB 判失败
- 新增 `check_page_marks.mjs`（Node 22 内置 WebSocket + CDP）：真机点按钮验证圆点数量/打灰/机位

### 踩到的坑
- `slots.json` 的 `camera_position` 是 **`[[x,y,z]]` 带一层数组**，`px_*.json` 的 `cam` 是 `[x,y,z]`；
  取错 → 相机 NaN → 一整张灰图但脚本「成功」（119KB 变 6KB）
- 文件是 CRLF，多行 Edit 匹配失败 → 用 Python 脚本 `newline=""` 做精确替换
- `apply(n)` 的选择器是 `[data-no]`，叠加层元素带同名属性就能自动复用，不用重写逻辑
