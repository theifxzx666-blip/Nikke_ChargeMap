## 1 章节归档：能识别到哪一层

用户此前的疑问是「之前几个方案能按章节识别」，结论要分两层说清：

| 层级 | 客户端有没有 | 判据 | 本文处置 |
|---|---|---|---|
| **章节级**（第 N 章用哪片区域） | **有** | `CampaignChapterTable.records[].chapter`（显示章号）+ `field_id = fcbg_<区域>_<NNN>` + 剧本前缀 `d_main_<章>_` + 关卡 id 段（35 章 = `6035xxx`） | 本轮据此全自动归档 |
| **关卡级**（3-7 关用哪张 sbg） | **没有** | `CampaignStageTable` 只有服务端下发的 `spot_id`（值 = stage id）；`campaignlevelmapgroup` 只有 `_stageId` + 坐标 | 不提供，粒度止于「该章的战场全集」 |

`docs/11` §1 原文写「第 N 章用哪张背景：没有」，只对**关卡级**成立，
对**章节级**是错的（H34/H35/H39 三章本来就是按 `chapter` + `field_id` 定的）。
本轮把这句话的口径改成上表。

### 1.1 归档规则（`工具/采集/apply_chapters.py`）

1. 区域取自 `field_id` 的中段；与 bundle 侧 `sbg_<区域>_*` 的差异逐条登记在 `ALIAS`：
   `fcbg_cityforestcrystal_*` ⇄ `sbg_cityforestundercrystal_*`（H28~34，docs/06 §1 实证）。
2. boss/布景变体的区域名带后缀，折回主战场区域（`swamplandjunglebbg008 → swamplandjungle`），
   与主战场同章 —— docs/06 §1 已写明 bbg008/009 属 35 章。
3. 区域在章节表里出现 → 落 `H<该区域最小章号>_<名称>`，**全部共用章号写进 `_章节.json` 的 `chapters`**；
   已人工核验的目录（`H34_晶化城市森林` / `H35_沼泽丛林` / `H39_母鲸领域`）不搬不改名，只补 `chapters`。
4. 区域在章节表里**不存在** → 落 `N_<区域>`，`_章节.json` 带 `note` 标待核。

## 2 本轮修掉的两处缺陷

### 2.1 断点续跑失效（会导致整批重采）

`run_one()` 的跳过判据是「按 `--chapter` + 短名拼出路径看 assembly 在不在」。
场景一旦归档到 `H35_沼泽丛林/`，再跑 `--run`（默认 `--chapter H00_待归档`）就查不到，
判定「没采过」→ 整批重采。

实测代价：v15 首采时，仓库原有的 16 个场景**全部被重采一遍**，产生 13 组同 arena 重复
（旧键 `001/c001/bbg008` 与 `short_name()` 生成的 `sj001/cc001/sjbbg008` 是两套键域）。

修复（`工具/采集/collect_all.py`）：

- 新增 `_done(short, stem)`：以 `registry.json` 为准，先查短名，再按 `arena` 反查旧键，
  任一命中且 `PATH.assembly()` 在位即跳过；
- 实测：`--run --only ac001,mw001,sj001,cc001,bbg008` 全部「跳过」，0 次 `adb dd`。

### 2.2 重复产物处置

13 组重复里 12 组三角面完全一致（重建无损），1 组不同：

| arena | 旧（仓库） | 新（本轮） | 结论 |
|---|---:|---:|---|
| `sbg_motherwhalefield_001/002/003` | 7974 / 6953 / 6320 | 31932 / 27968 / 25620 | 旧的是 `z=zmin` 修复前版本，**换新** |
| `sbg_motherwhalefieldbmf002_001` | 3061 | 11982 | 同上，**换新** |
| 其余 12 个（sj 5 + bbg 2 + cc 5） | 一致 | 一致 | 保留旧键旧目录名，内容换新 |

处置原则：**保留旧键 + 旧目录名**（文档、页面、`分析/` 都引它），内容换成新采的；
旧内容进 `回收站/_v15重复_20261028/`。目录内装配/glb/slots 的文件名同步改回旧键，
否则 `PATH.assembly()` 找不到（首次 `gen_catalog --check` 报了 13 项「缺 assembly」）。

### 2.3 场景卡缺 `chapter` 段 → 清单显示「第 None 章」

`gen_catalog.py` 的「章节」列取自**场景卡**的 `chapter{display,chapter_id}`，不是 `_章节.json`。
`collect_all.make_scene()` 只写 `chapter_dir`，不写 `chapter` 段，于是重生成的三张表单里
章节列全是 `第 None 章`。已在 `apply_chapters.py` 里回填（display 取自 `_章节.json` 或目录名），
并让 `gen_catalog` 把 `N_*` 目录显示成「非主线/待核」而不是「第 0 章」。

## 5 第二轮（2026-10-28）：命名双语化 · 全貌预览 · 全览图

用户提了三条，全部落地，规范写进 `PROMPT.md §21`。

### 5.1 目录名改成「章号_中文名_英文名」

25 个目录统一成人能读、机也能读的形态（中文在前，用户裁决）：

```
H35_沼泽丛林        →  H35_沼泽丛林_swamplandjungle
H00_cityforest      →  H00_城市林地_cityforest
N_tower             →  N_无限之塔_tower
```

- 英文段**只认 bundle 的 region**（`sbg_<region>_<NN>`），与 `registry.region` 逐字符相等；章节表那套 `cityforestcrystal` 不允许出现在目录名里。
- 中文名分三级来源写进 `_章节.json.name_source`：`official` / `inherited` / `translit`。
- 场景目录名、`arena` 键、数据文件名**一个都没动**（S1/S2 不变）。
- 脚本 `工具/采集/rename_chapters.py`（`--dry` 可演练），同名表 `NAME` 是唯一译名来源，`apply_chapters.py` 也改成从这里取。

### 5.2 官方章节名终于取到了

`CampaignChapterTable` 每行带 `name_localkey = Locale_Stage:chapter_name_NN`。这个库在**国服 PC 客户端**：

```
E:\[0]WeGame\...\胜利女神：新的希望(2002017)\nikke_Data\runtime_data\saus\saus\lss\Locale_Stage.lss
```

`.lss` 是 SQLite，列名带连字符（`zh-CN`）。**必须复制到本地再打开** —— 原路径含 `[0]`、中文、全角冒号，URI 形式直接 `unable to open database file`。

取到 0~48 章全部官方名（00 坠落 / 01 侵蚀 / … / 35 沟通 / 39 因子 / 48 重生），落到
`资源库/共享依赖/其他/chapter_names_zh.json`，再由脚本写进 `_章节.json.chapter_names`。
**章节名不进目录名**：35 章叫「沟通」，跟战场长相无关，塞进目录只会让人认不出是哪。

另外 7 个区域的官方中文名是从 lss 里查出来的，不是翻的：
`iceland=雪原`（StageTheme_Name）、`desert=沙漠`、`simulationRoom=模拟室`、
`lostsector=迷失地区`（**不是**「失落区域」）、`tower=无限之塔`、`gravedigger=掘墓`、`whitearkcity=白色方舟城`。
其余 14 个 `translit` 在清单末尾单列「待核译名」。

### 5.3 场景全貌预览图（112 张 PNG）

`正式产物/场景图/预览/<arena>.png`，1920×1080，纯场景。

`fp.html` 新增 `?view=overview` 分支：从 glb 包围盒算机位（`elev=18°`，距离按水平/垂直分别求再取大值），
不依赖 `slots.json` 的阵位相机。踩到四个坑，全部记在代码注释里：

| 坑 | 现象 | 修法 |
|---|---|---|
| `cam.far` 改了没重算投影 | 整场景被远裁剪，画面纯灰 | `cam.updateProjectionMatrix()` |
| 天空球球心留在原点 | 远景机位看到球的下半部，画面多一块灰圆 | 球心跟随相机，半径随场景放大 |
| 距离公式两头算宽 | d 偏大 45%，场景缩成一小块 | 水平只算 `sz.x`，垂直算 `y·cosθ + z·sinθ` |
| `hud=0` 没关 `#scrim` | 每张图左上角固定一块暗角 | 隐藏列表补 `scrim` |

### 5.4 全览图

每格缩略图 520×288 + `arena` / 中文名 / 英文名三行字，另出 `全览图.md` 索引表。

### 5.5 查出 38 个场景的地面被静默丢掉

用户看图发现「场景飘在空中」，顺这条线查到的真因：

`export_glb.ground_tile()` 只匹配 `*_ground01_c.png`，而实际有四种命名：
`ground01_c`(76) / `ground_c`(29) / `ground02_c`(20) / `ground03_c`(4)。
后 38 个场景拿到 `None` → glb 里没有 `GROUND` 节点 → **导出不报错**。

贴图本身不缺（glb 的 `images` 全内嵌，`uri` 计数 0）。修：正则 `_ground(\d+)?_c\.png$`，
rank 优先 01→02→03→无编号，crop 参数不变（三类图都是「一张纵向 4 段」的透视地面）。重导 38 个 glb 共 18 秒。
