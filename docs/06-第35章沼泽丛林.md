## 1 章节定位（可复现，不靠猜）

`CampaignChapterTable` 里 `id` 只是主键，真正的章节号是 `chapter` 字段；用关卡剧本反查最硬：

| chapter_id | `chapter` | 关卡 id | 剧本 | `field_id` | 显示章节 |
|---:|---:|---|---|---|---|
| 35 | 34 | 6034001… | `d_main_34_01_s` | `fcbg_cityforestcrystal_007` | 第 34 章（晶化城市森林） |
| **36** | **35** | **6035001…** | **`d_main_35_01`** | **`fcbg_swamplandjungle_001`** | **第 35 章（沼泽丛林）** |

35 章构成（`CampaignStageTable` 里 `chapter_id == 36` 的全部记录）：

- 共 **101 条**：`chapter_mod` Normal 46 / Hard 46 / Story 9；`stage_category` Normal 64 / Hard 30 / Extra 4 / **Boss 3**
- 怪物等级 **348 ~ 362**；关卡 id 段 `6035001 ~ 6035046`（Hard 镜像 `7035xxx`）
- **Boss 关只有一条**：`6035044`（`d_main_35_09_s`，Hard 镜像 `7035044`，Story `8035009`），
  `monster_id = 13100101` —— 就是你说的圣甲虫那条线
- `campaignlevelmapgroup_assets_fcbg_swamplandjungle_001_*.bundle` 里的 `_stageId` 全部落在 `6035xxx`，
  与章节对得上（这是从包内直接读的，不是推断）

**仍然断的一环**：`stage → 具体背景`（哪一关用 001 还是 003）客户端里没有表。
`CampaignStageTable` 只有服务端下发的 `spot_id`，`campaignlevelmapgroup` 只有 `_stageId` + 坐标。
所以给的是「35 章的战场全集」，不是「3-7 关用第几张图」。

## 2 还原链路

```bash
cd 数据
# 1) 拆包：按场景名抓 hd 主场景，自动排除 _rightclear/_midclear 与 (sd)
python extract_sbg_cf.py swamplandjungle          # 若已存在 原始bundle/sbg/sbg_swamplandjungle_00N.bundle 可跳过
python extract_sbg_cf.py swamplandjunglebbg       # boss 背景 008/009

# 2) 原生装配（顶点 / 三角索引 / 世界矩阵 / 分组 / 锚点 / 材质 / 雾）
python build_assembly.py 原始bundle/sbg/sbg_swamplandjungle_001.bundle 导出/assembly_001.json
python build_assembly.py 原始bundle/sbg_boss/sbg_swamplandjunglebbg008.bundle 导出/assembly_bbg008.json

# 3) 贴图 → glTF
python dump_textures.py 001 002 003 004 005
python export_glb.py 001 002 003 004 005 bbg008 bbg009

# 4) 像素级选点 → 可信度 → 审计 → 轮换（顺序不能乱）
python scan_px.py 001 && python verify_px.py 001 --sim=300 && python audit_px.py 001 && python sim_charge.py 001
```

`sim_charge.py` 必须排在 `verify_px.py` 之后：`verify_px.py` 会整份重写 `px_*.json`，轮换结果写在
`px_*.json → verify.field_sim`，被覆盖就没了。

## 6 图像质量：这轮修的三处

| 现象 | 原因 | 处置 |
|---|---|---|
| 物体缺面、像穿模 | 上面第 2 条：z=zmin 丢侧壁（只剩 24.5% 三角面） | 全量重跑，三角面 ×4 |
| 整体发白、像蒙灰 | `viewer/fp.html` 把每个材质 `color` 乘了 **1.18**，还显式 `material.fog = false` | 增益回 1.0，开启 `FogExp2(0.4627 灰, 0.006)`（雾色取自材质的 `_FogColor`），画布加 `contrast(1.05) saturate(1.06)` |
| 远景出现硬边灰矩形 | `*_fog01` 雾片被当不透明卡渲（软 alpha 用错模式） | 导出改为按 alpha 分布分流：不透明占比 ≥50% 用 MASK（树叶/栅栏），否则 BLEND（雾片/光斑）；雾片同时从三维里剔除，雾改由场景指数雾承担 |

顺手修的坑：`export_glb.py` 现在给 glb URL 加时间戳，避免改完几何后浏览器仍加载旧 glb；
`audit_px.py` 在「0 个达标点」的战场上不再崩（`max()` 空集）。

## 7 已知限制

- **没有实机截图校准**：光照/阴影/后处理（bloom、vignette、颜色调整）都没有重建，
  颜色是「贴图原色 + 均匀增益」，不是游戏内的最终成像。
- **近远景背景画片**（`_nf_*`，如 `nf_deepforest01`、`nf_rock09`）在游戏里走视差层滚动，
  我们按世界坐标静态放置，所以其边缘可能在画面里露硬边。这是当前最明显的观感缺陷。
  想要更干净可以先 `BG_SKIP=1` 重导 glb（会一起丢掉远景森林，画面偏空）。
- **天空盒**只有 side / upper / under 三张，现在把 side 贴在球面上，极点会拉伸。
- `stage → 背景` 仍不可解，只能给战场全集。
- 相机俯角 / FOV 未标定（俯角按 0 处理），像素坐标只在 16:9 有效。
- `hpdamage_limit=30` 语义未定，轮换模型 A/B 两种假设差 1 倍。
- 敌人 / 队友 / 残骸遮挡、换弹时间未计入。
