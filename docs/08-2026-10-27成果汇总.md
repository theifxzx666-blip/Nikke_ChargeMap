## 1 一句话

今天做的事可以概括成 **「把错的章节号改回来、把丢掉的三角面补回来、把点位从图片里挖出来」** ——
三件事里有两件是之前一直没被发现的静默错误，一件是架构问题。

| # | 症状（用户原话） | 真实原因 | 是否影响最终数字 |

## 2 六个根因（按发现顺序）

### 2.1 章节号取错字段

`CampaignChapterTable` 的 `id` 是主键，真正的章节号是 `chapter` 字段（= `chapter_id − 1`）。
用关卡剧本反查是铁证：

| 区域 | chapter_id | chapter | 剧本 | field_id | 结论 |
|---|---:|---:|---|---|---|
| 沼泽丛林 | 36 | **35** | `d_main_35_*` | `fcbg_swamplandjungle_001` | 第 35 章 |
| 晶化城市森林 | 35 | **34** | `d_main_34_*` | `fcbg_cityforestcrystal_007` | 第 34 章 |

35 章 Boss 关只有一条 `6035044`（`d_main_35_09_s`，`monster_id 13100101`，Hard 镜像 `7035044`）。

### 2.2 `build_assembly.py` 只导出 z 最小一层顶点

原实现是为**单面平板**设的减半优化。盒状件的侧壁三角形**跨两层顶点**，被整片丢掉 ——
三角面只剩 **24.5%**，射线从侧壁缺口直接穿过去，遮挡失效、段数系统性虚高。

```
沼泽 001：15,276 → 62,070 三角面（4.06×）
晶化 c001： 9,362 → 38,162 三角面（4.08×）
```

这是「看着缺面、像穿模」和「段数虚高」的**同一个**根因。

### 2.3 `*_col` 地形碰撞网格混进可视几何

`ground_col` 一类是碰撞体不是美术。不滤掉，射线会在第一米撞上「隐形地板」，段数全归零。
修法：`if base.endswith("_col") or "_col_" in base: continue`（ground 计数 5→4）。

### 2.4 alpha 一律走 MASK

原实现所有带 alpha 的贴图都用 `alphaMode=MASK, alphaCutoff=0.5`。
`*_fog01` 雾片的 alpha 均值只有 **0.16**、85.9% 像素低于 128，被当成不透明矩形整片糊成灰块。

改成按 alpha 分布分流：不透明像素 ≥50% → MASK（树叶/栅栏）；否则 → BLEND（雾片/光斑）。

### 2.5 视口材质增益 1.18 + 关雾

`viewer/fp.html` 把每个材质 `color` 乘 `bright`（默认 1.18），且显式 `material.fog = false`。
两者叠加就是「像蒙了一层灰」。改成 1.0 增益 + `FogExp2(0.4627, 0.006)` + 画布 `contrast(1.05) saturate(1.06)`。

### 2.6 点位被画进图片像素（今天最晚发现的）

`fp.html` 的点位是 three.js 的 `dotSprite` / `labelSprite` ——
截图时它们和其他像素一起被写进 `fp_001.png`。页面上的 `<img>` 只是一张**静态位图**，
前端再怎么切控件也不可能重绘它。

> **这一条解释了「上一轮修了但没修好」**：上轮把 5 个阵位分别出图，图片确实换了，
> 但**同一张图上的点位数量永远变不了**。加图片数量解决不了，必须换架构。

## 3 修法：图归图，点归点

| 层 | 改法 | 落点 |
|---|---|---|
| 出图 | 加 `dots=0&hud=0`，只出纯场景 | `viewer/fp.html` + `render_views.py` |
| 点位 | `mark_html()` 把 `px`（1600×900 基准）换算成百分比，生成绝对定位 `<i class="dm">` | `gen_fp_page.py` |
| 筛选 | 复用已有 `data-no`（显示几个）/ `data-ss`（各阵位段数），自动跟随 | 同上 |
| 机位 | 「机位 · 我站的掩体」切换条，快捷键 Q/W/E/R/T，**默认 3 号位** | 同上 |
| 对照 | 原「我的掩体」改名「跨阵位对照」：同一瞄准点在别的阵位还能打几段 | 同上 |

**真机验证**（`数据/check_page_marks.mjs`，无头 Chrome + CDP 真实点击后读 DOM，不是只看 HTML 结构）：

| 操作 | 图上可见圆点 | 表格行数 |
|---|---:|---:|
| 默认（5 个 / 3 号位） | 5（①~⑤） | 5 |
| 点「全部」 | 12（①~⑫） | 12 |
| 跨阵位对照 = 2 号 | 12，其中 8 个变灰划线 | 12 |
| 切「1 号位」 | 12 个全重算，首点 50.91% → 59.84% | 12 |

## 4 阵位差异有多大（拆包 `slots.json`，15 个战场共用一套布局）

| 阵位 | 相机 x, z | 相对 3 号位 | 说明 |
|---|---|---:|---|
| cover_1 | −4.8, 0.0 | −5.4 m | 最左 |
| cover_2 | −2.1, −2.0 | −2.7 m | 左前（z 后退 2m） |
| **cover_3** | **0.6, 0.0** | **0** | **游戏进图默认** |
| cover_4 | 3.3, −2.0 | +2.7 m | 右前 |
| cover_5 | 6.0, 0.0 | +5.4 m | 最右 |

相机横跨 **10.8 m**，在 20 m 目标上就是 **±15° 方位差** —— 足以把中线目标推到画面边缘，
也足以让被掩体挡住的走廊露出来。所以「照 3 号位的点位表去站别的掩体」是错的。

## 6 今天踩的坑（都已修，留档防复犯）

| 坑 | 表现 | 修法 |
|---|---|---|
| `git push` 被拒 | `fetch first`，远端有 3 个未合入提交 | `git rebase origin/main`，`GIT_EDITOR=true` 续跑 |
| 推送 SSL 失败 | `schannel: failed to receive handshake` | 只走 Clash `127.0.0.1:7897`，**大小写变量都要覆盖**（环境里预设了小写坏值），且需 `dangerouslyDisableSandbox` |
| `git commit -m @'...'@` | `@` 被写进提交信息 | 改 `git commit -F _msg.txt` |
| 系统 python 无 UnityPy | `python` 指向 workbuddy 内置 | 全程用 `~/.workbuddy/binaries/python/envs/default/Scripts/python` |
| `/tmp` 不可用 | Windows bash 下路径无效 | 改用 `_cmp/` 目录或 `git show HEAD:path >` |
| Chrome 截图加载旧 glb | 改了但不生效 | URL 加 `?v=${Date.now()}` 缓存穿透 |
| 8899 双实例 | 两个 PID 抢端口，curl 经环境代理返回 502 | `taskkill` 后单实例重启，全程 `curl --noproxy '*'` |
| `slots.json` 相机多一层数组 | `[[-4.8,0,0]]` 直接取 `C[0]` → NaN → 整张图变灰，脚本仍报成功 | 取 `SC.camera_position[0]`；`render_views.py` 加空白检测（PNG < 200KB 直接报错） |
| `sim_charge.py` 空战场崩溃 | `bbg008` 三组 `IndexError` | 0 个达标点时写全 0 结果，不跳过 |
| `audit_px.py` 空集崩溃 | `max() iterable argument is empty` | `perp_med/perp_max` 加判空 |
| 串行批处理太慢 | 35 组要 87 分钟 | `batch_views.py` 组间并行（12 核 6 路）→ **16 分钟**，并加断点续跑 |
| `verify_px.py` 会整份重写 `px_*.json` | 跑在 `sim_charge.py` 之后会冲掉轮换结果 | 顺序固定：`scan → verify → audit → sim` |
